BatchNorm：训练时看一批图，部署时为什么能折叠进卷积？

结论：BatchNorm 在训练时利用每个通道的一批激活计算统计量；在常规推理时改用固定统计量，成为逐通道的仿射变换。因此，紧接卷积的冻结 BN 可以吸收进卷积权重与偏置。训练行为、推理行为、折叠后的数值行为必须分别验证，“图里没有 BN 节点”本身不代表部署正确。

类型：CV / 深度学习基础 / 模型部署。发布与实验：2026-11-23。前置：均值、方差、卷积。本文用真实手写数字训练小型 CNN，核对冻结统计量、批次依赖和折叠误差；没有测 GPU、HTP 或 NPU 延迟。所有本地数值由文末脚本生成，论文历史结果另行标记。

1｜直觉：训练时“看同伴”，推理时“用固定刻度”

想象卷积输出的某个通道像一把不断变化的尺子：前面权重更新后，它的激活数值范围也会变化。BN 先估计这个通道的中心与尺度，再把数值转换到新的坐标中。接着，它用可学习的 γ 和 β 重新缩放、平移，让模型自己选择需要的表示范围。BN 并不强迫最后输出始终零均值、单位方差。

最容易漏掉的是“尺子的刻度从哪里来”。训练模式下，当前输入批次提供刻度；常规 eval 模式下，训练期间累积的 running mean / running variance 提供固定刻度。于是，同一张图在训练模式下可能受同批其他图影响；冻结推理时，它应当独立于同伴。这个区别也是 BN 能否静态折叠的分界。[1][2]

TrainingConv → 当前批次 μ / v → γ、β → ReLU
同时更新 running buffers
InferenceConv → 固定 μ̄ / v̄ → γ、β → ReLU
不再从输入求新统计量
Folded inferenceConv(W′, b′) → ReLU
μ̄、v̄、γ、β 已进入参数

2｜CNN 的 BatchNorm 到底沿哪些轴求统计？

以 NCHW 张量为例，N 是图片数量，C 是通道数，H、W 是特征图高宽。对每一个 c，BN2d 在 N、H、W 上一起求统计量；每个通道有一套均值、方差、γ、β。它既不是每张图独立归一化，也不是把所有通道混在一起。[1][2]

M = N × H × W
μc = (1/M) Σn,h,w zn,c,h,w
vc = (1/M) Σn,h,w (zn,c,h,w − μc)²
yn,c,h,w = γc (zn,c,h,w − μc) / √(vc + ε) + βc
LaTeX
\mu_c=\frac{1}{M}\sum_{n,h,w}z_{n,c,h,w},\quad v_c=\frac{1}{M}\sum_{n,h,w}(z_{n,c,h,w}-\mu_c)^2\ny_{n,c,h,w}=\gamma_c\frac{z_{n,c,h,w}-\mu_c}{\sqrt{v_c+\epsilon}}+\beta_c

z 是卷积的输出，y 是 BN 输出；ε 是放在平方根内部的小正数，避免除以零并影响低方差通道的尺度。γ、β 是通过梯度学习的参数，μ、v 是这次 forward 的统计量。数学上计算方差使用 M 分母；PyTorch 的训练 forward 也用这一有偏估计。running variance 的更新则使用 M−1 分母的无偏估计，二者不能混淆。[2]

N=1 不一定意味着 BN2d 完全没有统计样本。只要 H×W 大于 1，同一张图的空间位置仍参与计算；但空间位置可能强相关，不能把 N×H×W 简单当成同样数量的独立图像。BN1d 遇到只有一个有效统计元素的训练输入则是另一种边界。将 NCHW 改成 NHWC 时，物理通道轴应随之改变；不能只改 shape 标签，仍对错误轴做归约。

3｜为什么引入 BN？原论文的动机与后来的修正

2015 年，Google 的 Sergey Ioffe 与 Christian Szegedy 提出 Batch Normalization，把归一化纳入可微计算图，让统计量也参与反向传播。它区别于在优化器步骤之外重新调整数据刻度：后者若忽略统计量对参数的依赖，会使更新与归一化相互抵消。原论文强调更高学习率、对初始化的适应性与一定的正则化效应。[1]

原论文在特定 ImageNet 网络和训练方案下报告，以约 14 倍更少的训练步数达到对照精度。这个数是论文实验结果，不是所有网络训练都能快 14 倍，也不是推理提速。其训练安排、学习率与其他改动需要一起阅读。本文的小 CNN 不用于复现该 ImageNet 比例。

BN 的原始解释强调 internal covariate shift：前层更新导致后层输入分布变化。但 Santurkar、Tsipras、Ilyas 与 Mądry 的 2018 年论文设计了“BN 后再加入随时间变化的噪声”等对照。分布稳定性被破坏后，BN 的训练优势仍可能保留；作者进一步分析了损失和梯度的局部平滑性。[3]

因此，较稳妥的结论是：BN 会改变优化问题与梯度行为，原论文给出了有效方法和实验；只靠“稳定输入分布”解释全部收益并不充分。平滑性分析也有模型与假设范围，不能扩展成对任何架构的统一因果证明。本文验证的是 BN 的计算语义与部署等价性，不测试这些训练机制孰为唯一原因。

反向传播也会看同伴

对一个通道，把 N/H/W 位置统一编号为 i。令 ĝi=∂L/∂yi，ẑi=(zi−μ)/√(v+ε)，则当前批次 BN 的输入梯度是：

∂L/∂zi = γ / √(v+ε) · [ ĝi − mean(ĝ) − ẑi mean(ĝ·ẑ) ]
LaTeX
\frac{\partial L}{\partial z_i}=\frac{\gamma}{\sqrt{v+\epsilon}}\left[g_i-\frac{1}{M}\sum_j g_j-\hat z_i\frac{1}{M}\sum_j g_j\hat z_j\right]

mean 是在同一通道的 M 个元素上求平均。与“直接乘固定缩放系数”相比，梯度还要减去整批梯度的均值，以及沿当前归一化激活方向的分量；ε>0 时，后一项不能简单理解为完全移除这个方向。这是统计量依赖输入所带来的真实链式求导，展示了同批元素在 backward 中也相互耦合。γ 的梯度是 Σ ĝ·ẑ，β 的梯度是 Σ ĝ。冻结 eval 的输入梯度才退化为固定系数 a·ĝ，所以把训练 BN 提前折叠会改变训练问题。[1] 文末脚本还用已训练网络的 32 张真实图核对该式与 autograd，最大绝对差为 4.657e-10。

此外，逐通道消去均值和调整方差，并不消除通道之间的相关性；BN 不是完整 whitening。原论文主动选择独立归一化各特征，避免计算并求逆完整协方差矩阵。

4｜eval 不等于“不计算梯度”：running buffers 是模型状态

PyTorch 默认 track_running_stats=True，训练时同时更新运行统计量。以 momentum=m 表示：

μ̄new = (1 − m) μ̄old + m μbatch
v̄new = (1 − m) v̄old + m vbatch, unbiased

默认 m=0.1，所以新批次占 10%，旧统计占 90%。这不是 Adam 或 SGD 的动量含义；不同框架也可能用互补的系数定义同名参数。默认指数移动平均不是严格的全训练集总体方差。保存模型时，running mean、running variance、批次计数也是 state_dict 的一部分。[2]

操作影响 BN 使用的统计量？是否禁止梯度？
model.eval()默认改用 running buffers否
torch.no_grad() / inference_mode()不会自行改变 train/eval是
requires_grad_(False)冻结 γ、β 的学习，不自行改变统计来源只针对相应参数
track_running_stats=Falseeval 仍使用批次统计，无法按常规方式静态折叠否

所以“冻结参数后导出”还需要确认模型模式；“no_grad 里跑了一遍”也不等于 eval。某些视觉微调流程只冻结 BN 统计而继续训练其他层，这与把整个网络切成 eval 是不同操作。在线重新估计统计量会改变模型函数，若重新采用这种策略，旧的折叠参数也必须重新生成。

5｜推导：固定 BN 怎样吸收进 Conv 权重与偏置？

对一个输出通道 c，卷积输出是 zc=Wc*x+bc，其中 * 表示卷积求和。eval 的 BN 是 aczc+dc。因为 a、d 已固定，直接把它们代入：

ac = γc / √(v̄c + ε)
W′c = ac Wc
b′c = βc + ac (bc − μ̄c)
BNeval(Conv(x; W,b)) = Conv(x; W′,b′)
LaTeX
a_c=\frac{\gamma_c}{\sqrt{\bar v_c+\epsilon}},\quad W^\prime_c=a_c W_c,\quad b^\prime_c=\beta_c+a_c(b_c-\bar\mu_c)

一个纯代数例子：若 γ=2、β=−1、μ̄=3，并且 v̄+ε=4，那么 a=1；原卷积偏置 b=5 折叠后 b′=−1+(5−3)=1，权重不变。这个例子只是说明运算，不是训练测量。

若原卷积没有 bias，就令 b=0，再生成新 bias。γ=0 时，该通道的折叠权重全为零，输出是 β；γ 为负数时，权重符号翻转，两种情况均合法。PyTorch 的 fuse_conv_bn_eval 正是实现这一转换，要求 Conv 与 BN 都处于 eval 且 running buffers 存在。[4][5]

scale = bn.weight / torch.sqrt(bn.running_var + bn.eps)
fused_weight = conv.weight * scale[:, None, None, None]
bias = torch.zeros_like(scale) if conv.bias is None else conv.bias
fused_bias = bn.bias + scale * (bias - bn.running_mean)

对标准 Conv2d，权重是 [Cout, Cin/groups, Kh, Kw]，应缩放 Cout 轴；grouped/depthwise 卷积也依这一输出通道定义。ConvTranspose 的参数布局不同，官方函数显式提供 transpose 参数，不能机械照搬上述广播。

ReLU 不能随意跨过去。Conv → BN → ReLU 可以先折叠紧邻的 Conv–BN；Conv → ReLU → BN 不能一般地按同一公式移走 BN，因为非线性夹在中间。若卷积输出还有其他消费者，仅替换这个卷积可能改变那些分支，需要按数据流处理。

8｜复杂度、访存与端侧：省下的是哪一层工作？

训练 BN 要对 NCHW 激活做统计归约和逐元素变换，工作量 O(NCHW)，逐通道统计状态 O(C)。训练 backward 还需保存或重算相关激活/统计量，不能把它当成一个可免费消失的层。常规推理 BN 则不再做批次归约，但独立 kernel 仍要读写整份激活。

Conv 的乘加规模约为 N·Hout·Wout·Cout·(Cin/groups)·Kh·Kw。离线折叠一次的成本是 O(卷积权重数)，运行时 Conv 的主要乘加数量并未下降，却可能省去独立 BN 的逐元素运算、调度和中间激活传输。以未经 fusion、需要物化输出的基线看，至少有一次 BN 输入读取与输出写入可能被消除；这是数据流分析，不是 DRAM 实测。

模型持久参数也要算清楚：原 BN 有 γ、β 两组可学习向量和均值、方差两组 buffers；无偏置卷积折叠后新产生一个 Cout 偏置向量，因此净节省不能简单说成“BN 参数全部删掉”。如果编译器早已执行等价融合，手动折叠未必再增加速度。小模型在 CPU 上的 Python 开销也不能代表 HTP kernel 收益。

在 QNN/HTP 等端侧链路，核对导出图是否用冻结统计量、输出通道轴是否正确、ε 是否保持一致，再看编译后的实际算子映射与端到端耗时。本文未调用 QNN，未测 DMA、峰值内存或 NPU 吞吐，因此不给出这些硬件数字。

10｜局限与替代：小 Batch、分布变化和其他归一化

BN 的训练统计可能受小 batch、相关空间位置、跨设备分片与分布变化影响。SyncBatchNorm 跨设备汇总统计，改变的是有效统计集合并引入通信；梯度累积不会自动让每次 forward 的 BN 看到一个大批次。检测、分割、视频等任务常因分辨率和内存限制只能使用小 batch。Wu 与 He 的 Group Normalization（2018）正针对这一问题，把统计放到每个样本内部的一组通道，而不是依赖 batch。[7]

GroupNorm、LayerNorm 的统计一般仍取决于当前输入，不能在普通推理时像冻结 BN 一样整体吸收进前一层卷积。它们的可学习仿射部分与输入依赖的归一化部分应区分。可折叠性来自统计量固定后函数成为仿射，不来自层名字里有 “Norm”。

此外，BN buffers 适配的是训练过程所见的激活分布。如果相机预处理、亮度范围、颜色顺序或数据排布在导出链路改变，完美的代数折叠也无法修复输入分布偏移。需要分别定位预处理一致性、统计状态、量化和后端误差，而不是把这些变化混成“模型太小”。

11｜总结与复现：先明确状态，再谈删除算子

值得记住的三件事：BN2d 的统计是逐通道、跨 N/H/W；train 和默认 eval 是两种计算语义；冻结且紧邻卷积的 BN 是可精确代数吸收的仿射变换。部署验证应同时包含中间值误差与原任务输出，不能仅验证不崩溃或节点数量。
