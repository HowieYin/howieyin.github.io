03｜Mistral Large 4：开放权重之后，真正的工程增量是什么

事件｜2026-10-29；P1；「延续此前事件」。 Mistral Large 4 此前已于 10-06 进入 Public Preview。本期新增是可下载的 FP8/NVFP4 权重、模型卡与配套推理实现，不能把 10-29 写成模型第一次出现。Hugging Face 10-29 发布文和 Mistral 官方模型卡交叉确认本期开放状态；Mistral 官网新闻页本次正文获取失败，不据此编造价格变更。S4 S5

技术解读。 该模型把“专家容量”和“上下文访问”做成两个独立稀疏维度：MoE Router 每 Token 选少量 FFN Experts；DSA Indexer 为每个 Query 选此前的 Key Positions。MLA 压缩 KV 表示；跨层共享再减少重复存储；NoPE、SSMax、LeRoPE 调节位置与长度行为。

架构项 官方模型卡 / vLLM 实现文
参数 / Context 约 1T 总参数；49B Active，含 Embedding/Output 为 52B；1M Context
Decoder 72 层；Hidden 6144；64 Attention Heads
MoE 第 0 层 Dense；其余 71 层为 128 Routed Experts，Top‑4＋1 Shared
MLA KV LoRA Rank 512；RoPE Dim 64；默认 fp8_ds_mla
DSA Top‑2048；44 层自有 Indexer，28 层复用此前层的 Top‑k
NoPE / KV Sharing 每 4 层之一 NoPE；39、43…71 共 9 层读 Layer 35 的 Latent KV
Vision Pixtral Encoder：30 层、Hidden 2048、14×14 Patch
DSpark 内置 3 层 Sliding-window MLA Drafter；独立 Draft KV Group

性能 / 数据。 Mistral 模型卡报告 AA Coding Agent Index 48%，与 GLM‑5.3 接近、平均 Token 少 47%；HF 发布文另报 49.8%。这是来源之间的口径/快照差异，本次未取得完全对齐的评测配置，不合并成一个确定分数，也不将差异解释为已证实的模型升级。S4 S5

vLLM 发布文按实际 Cache Layout 给出 47,136 B/Token，其中 Latent 41,328 B、Indexer 5,808 B；每层都自有 KV 的假设为 53,040 B/Token，相比少约 11.1%。该数字对应文中的每 GPU、尚未按 Context Parallelism 分片的表示，不是集群总显存；也不能把 “Top‑2048”理解成历史 KV 只保留 2048 Token。S6

为什么值得关注。 稀疏 Attention 减少访问位置，不自动消除历史存储；Index Cache、跨层共享、DCP 和 Host Offload 仍需共同设计。KV Sharing 是训练时形成的模型结构，不能对普通模型任意让两层共享缓存并期待精度不变。

判断｜本文分析。 可作为稀疏 MLA、KV 共享、DSpark 与多模态组合的代码研究对象。1T 模型的权重驻留仍按总参数而非 Active Parameters 计算；“只激活 49B”不意味着可像 49B Dense 模型一样单卡部署。许可证是 Mistral Ecosystem Open-Weight License；官方模型卡明确 Model-as-a-Service 业务需要单独商业许可，本报告不将其称为无条件 MIT。

来源： Mistral 官方模型卡；HF 10-29 发布介绍；vLLM 官方实现。

Mistral Large 4 部署：DCP 的容量收益不是免费延迟收益

事件｜2026-10-29；P1。 本期 Day‑0 vLLM 实现针对 ML4 增加 MRV2、Breakable CUDA Graphs、DCP/PCP、DSpark、NIXL P/D 与跨层共享适配。这是部署增量；不能把正在 Upstream 的每项工作都写成通用稳定版已包含。S6

技术解读。 MLA 只有一个 Latent KV Head，普通 TP 中会在 Rank 间复制。DCP 按 Token 分片减少复制，代价是每步交换 Indexer 候选、LSE 和 Attention 结果。实现将 All-gather/Reduce-scatter 的若干路径改为对称内存通信、直接 Top‑k 交换和有效位置压缩，减少通信与小 Kernel 开销。

性能 / 数据｜vLLM 团队报告；不是本地复测。

为什么值得关注。 本文特别值得读的不是最高 TPS，而是 PCP 的一个正确性修复：Graph Capture 把 Prefill/Decode Split 冻结，导致运行时 Gather 使用错误边界；只把动态 Gather 作为 Eager Break，其余 Cache Write 保持在 Graph 中，恢复正确行为。源文的 GSM8K‑200 从 0.315→0.975，带 DSpark 为 0.980，是该特定配置的验证，不能视为模型普遍“准确率翻三倍”。

判断｜本文分析。 对长 Agent Session，先判断是否已受 KV 容量约束，再决定 DCP。复测需同时覆盖动态 Batch Split、共享层写入跳过、Indexer Cache、Draft Reject/回滚和 P/D 分片组合。HF 文给出的部分示例用 --enforce-eager，vLLM 专用实现强调 Graph；上线应固定具体镜像/Commit，不能拼接不同页面的 Flag。

04｜Liquid AI LFM3：硬件参与架构搜索，端侧能力来自整条链

事件｜2026-10-27；P1。 Liquid AI 发布文本、视觉、音频、Omni 和 Decision 的 LFM3 家族，约 2B 级，Base 与后训练权重可获取。发布文称架构搜索覆盖 14 个设备/后端组合，包括 Apple/AMD、Arm/x86、手机和 Qualcomm Hexagon；这不证明所有格式在所有 NPU 上已同日稳定支持。S7

技术解读。 文本骨干 24 层：13 个 Gated Short Convolution（Kernel 7）、5 个 SWA（Window 256）、6 个 Global GQA。Head-wise Sigmoid Gate、Partial RoPE、Sandwich Norm 用于表达力和数值稳定。卷积状态与 SWA 有界，Global Attention 的 KV 仍随 Context 增长。

训练包含 22T Pretraining Tokens，最后 3.5T 为 Curated Mid-training；文本后训练经过 SFT、Mixed RL、六域教师的 On-policy Distillation、真实 Harness 内 Agentic RL。不是只把 Attention 换成卷积就获得全部任务收益。

05｜GAAC：无损 KV 的价值在少搬数据，而不在压缩率榜首

事件｜2026-10-28 03:03:51 UTC；P1。 Notre Dame 的 Yipin Guo、Arun M George、Siddharth Joshi 首次提交 GAAC，arXiv:2610.38210v1。与上期 KV‑Surgeon 的离线、带近似的上下文压缩不同，本次研究逐比特保留 KV 数值并将解压融合到 Decode Attention。S11 S12

技术解读。

  1. BF16 的 Sign＋Mantissa 原样存成 1 Byte，只压缩 8-bit Exponent。离线为每 Layer/Head/Channel 标定连续指数区间。
  2. 每 8 个元素共用 2-bit Tag，选择 3-bit Offset、4-bit Offset 或 Raw Exponent。越界时扩大组编码，不能把值截断到标定区间。
  3. 3-bit 模式每元素占 8＋3＋0.25＝11.25 bit；理论全为该模式的比例为 16/11.25≈1.422×。实际 Tag、较宽模式和固定 Slot 进一步降低有效节省。
  4. Attention 按 Tile 读压缩数据，边恢复边计算，不先展开整份 Cache。新 Token 进入 BF16 Tail，Block 满后压缩进固定容量 Slot；过大时保留 Raw Block。

性能 / 数据｜原论文实验。 主要硬件为 DGX Spark GB10、48 SM、128GB Unified LPDDR5x，实测带宽约 240GB/s；模型用 AWQ W4A16，Serving 基线为 vLLM 0.17.1。它不是与本期 vLLM 主线最新 Kernel 的对照。

FP8 再压缩 E4M3 1.09–1.14×；E5M2 1.25–1.30× FP8 本身相对 BF16 可能有损；GAAC 仅精确保留传入 FP8

本期总结与技术趋势判断

以下为分析，不是厂商已证明的普遍规律。

  • 任务成本正在成为主要竞争指标。 Terra 的低价视觉行动、Fusion 的路由/编排、LFM3 的小模型专用化都是同一方向，但单 Token 价格、输出效率、成功率、重试与工具成本要一起评估。
  • KV 从一个 Tensor 变成完整状态系统。 ML4 设计表示和共享；GAAC 将编码融入 Kernel；Mooncake 管理所有权与租期；NIXL 检查布局映射。只优化带宽或显存，无法代替生命周期和正确性。
  • 更多稀疏性意味着更复杂的布局。 MoE Expert Sparsity、Attention Top‑k、SWA、有界 Conv/SSM State 与跨层 KV Sharing 各自解决不同瓶颈，不能用一个“稀疏倍率”概括。
  • 端侧收益要求架构、量化、导出和 Runtime 联合设计。 LFM3 的多设备架构搜索和 MLX 的数值修复说明，精度与速度都可能在转换/执行环节失去；产品级测试不能只测语言能力。
  • 容量和延迟是不同目标。 DCP 增加近 8×容量仍可能增加单步 TPOT；GAAC 多并发总吞吐增长仍可能主要来自 Batch 增大。每次 Benchmark 都要说明优化的是哪个目标。
  • 行业扩张与现金压力并存。 云业务增长、TPU 系统销售与 Bedrock Token 放量提供需求证据；资本开支和自由现金流则约束供给效率。不要据其中一个数字单独预测行业转折。
