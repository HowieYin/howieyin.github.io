01｜Inkling 2 Small：稀疏模型、视觉与长时自动研究

事件｜2026-11-05。 Thinking Machines 发布 Inkling 2 Small，通过 Tinker API / Playground 提供微调与采样。模型初始权重未开放；官方计划在外部安全测试与红队评估后，于下一周以 Apache-2.0 发布权重。因此，本期不能把“宣布计划开源”写成“已有开放权重可部署”。S1、S2

技术解读。 594B 总参数、17B 激活参数、48 层 Decoder、384 个 MoE 专家中选择 8 个，结合局部与全局 Attention，支持可变推理预算。视觉编码器约 292M 参数，基于 Perception Encoder，20×20 像素 Patch 后做 2×2 Pooling。模型宣称最高 1M 上下文；具体端点限制与价格需要独立确认。

17B 激活参数主要影响每 Token 的专家计算量，不代表仅需加载 17B 权重。全量权重存储、专家通信、长上下文 KV 与视觉编码仍决定部署成本。局部 Attention 可降低部分层的历史访问，但全局层、图像 Token 和服务调度不会随之消失。公开信息尚不足以估算真实 TTFT、TPOT、显存或功耗，也不能按激活参数把它归为可直接部署到手机的小模型。

判断。 值得持续跟踪权重、许可证落实和本地推理配置。对 Howie，先做真实截图 / PDF 的分任务评估，再决定是否替换 OCR / GUI 模型；当前官方定位分数无法提供 TP、FP、TN、FN、Precision、Recall、F1。本次返回的价格文档仍显示旧 Inkling 系列，没有核实 Inkling 2 Small 的新价格，不借用旧型号价格或上下文端点。S34

04｜GPT-Live 出站 SIP：创建 Session 后还有完整呼叫生命周期

事件｜2026-11-02。 OpenAI 宣布 Live API 出站电话能力向所有组织开放。应用使用 Live API 建立 Session，电话目标采用 E.164，Provider SIP 地址使用 TLS 与 SDES-SRTP，后端仍承担业务逻辑与工具执行。S3、S7

技术解读。 关键链路是“创建 Session → 拨号 / Ringing → 接通或失败 → Sideband 事件与工具 → 关闭 / 计费”。POST /v1/live/sessions 返回 200 与 Session ID 只意味着初始化成功，不能当作电话已经接通；异步 transport.failed 仍可能随后到达。

Sideband WebSocket 应立即附着到已有 Session，而不再次 session.start。文档只回放此前约 3 秒事件；迟附着可能错过状态，重连又可能收到重复事件。应按 event_id 去重，并保证有副作用的工具只有一个执行归属，避免同一个回调被主连接与 Sideband 各执行一次。

性能与数据。 文档规定 Ringing 最长 3 分钟，接通后最长 2 小时。应采集 Ringing / Answered / Failed、最终 Usage 与 session.closed；本期没有新的通用音频延迟、识别准确率或端到端呼叫成功率测量，费用还涉及电话 Provider 与业务后端。

为什么值得关注。 这类 Agent 的错误通常发生在生命周期、重连和回调层：模型生成正确的工具调用，也可能因为重复消费或错判接通状态而让整个业务失败。

判断。 对 Howie 最可迁移的是 Native Runner / JNI / 回调链的设计思路：Session 状态显式化、消息幂等、单一副作用执行者、最终状态收口。复测时加入“创建成功后失败、附着延迟、断线重连、重复工具事件、终止时结算”场景；不能只测成功路径的平均延迟。

来源： S3、S7。

05｜Qualcomm HBC：从近存计算路线图走向硅片验证

事件｜2026-11-02。 Qualcomm 公布首代 High Bandwidth Compute 工作硅片验证，包括完整读写与近存计算，使用随机权重 / 激活和接近生产的尺寸。数据中心产品已 Tape-out、进入早期 Bring-up；AI250 Dragonfly 预计 2027 年上半年送样。S8、S9

技术解读。 DRAM-on-logic 将存储与计算在物理上靠近，通过晶圆键合、冗余 / Remap、测试与热设计减少远距离搬运。对 Decode 这种经常由权重读取限制的负载，减少搬运有潜在价值；对高复用、大矩阵 Prefill，则还要评估计算效率、激活流量和算子支持。

06｜NVIDIA Vera：Agent CPU 有价值，性能分母必须核对

11｜BitDecoding-FP4：低比特 KV 与低比特 Attention 联合设计

事件｜arXiv v1：2026-11-06 18:13:54 UTC，即北京时间 11 月 7 日。 Edinburgh 与 Tencent Hunyuan 的 BitDecoding-FP4 公开论文和代码，面向原生 FP4 Attention，支持 GQA / MLA、Dense / MoE 等配置。S19–S22

技术解读。 不仅将 K/V 以低比特存储，还把 Q、K、Softmax 概率 P、V 与 Scale 纳入 FP4 计算路径：

  1. Query 双残差表示： q ≈ q1 + r2，用第二个 FP4 分量补偿第一次量化。论文所称 60%→1% 对应 Query 误差在总 Logit MSE 中的贡献比例变化，不是整个模型总误差降到 1%。

12｜DARIC：独立 Chunk 复用需要处理跨 Chunk 依赖

事件｜2026-11-06 07:41:55 UTC。 Lenovo Research 公开 DARIC 的 arXiv v1 与 vLLM 插件，元数据标示 SIGMOD 2027 接收。仓库 10 月创建不能证明论文已在 10 月首次公开，本期以 v1 提交时间为事件依据。S23–S25

技术解读。 连续 Prefix Cache 遇到前面未命中片段时，通常不能复用后续位置的缓存。DARIC 将上下文按 Chunk 独立缓存，即使排列为 [B,A,D,C]、D 未缓存，也可尝试复用已有 C，而不要求整段从开头连续命中。

关键困难有两层：一是位置变化，要处理 RoPE / Block Alignment；二是同样 Token 放到不同前文之后，Attention 的输入分布可能已改变。重编码位置不能恢复丢失的跨 Chunk Attention。DARIC 用分布感知的先验选择部分重算，避免每次在线计算完整 KV 差异或固定重算比例造成额外开销；这是一种近似复用策略，不是任意重排严格等价。

输入处理器识别分隔符并 Padding 到 Block 倍数；Scheduler / Worker 管理缓存与重算。缓存匹配仍要求实际 Chunk Token 对应，不能把语义相近的文本视为同一个 KV。

性能与数据。 作者报告相对已有方案 TTFT 加速 1.1–4.5×、质量损失很小；本次没有核实通用 TPOT 改善、RAM 压缩比例或全部实验硬件条件，因此不补填。

公开仓库复现默认包含最大长度 8,192、GPU Memory Utilization 0.9、单 CUDA Device、扩展 WikiMQA；150 个单输出 Warm-up 后运行 600 个主请求，Rate=1、Burstiness=100。这是代码的复现默认，不等于最高 4.5× 论文结果的已证实测试配置。 文档要求 Python 3.12、CUDA、vLLM≥0.11，安装示例固定 0.30.0，并通过 VLLM_PLUGINS=daric / DARICConnector 设置 Host 与 Disk Budget。

为什么值得关注。 RAG 文档、工具描述、Agent 历史与用户消息常重复出现但位置改变，非连续缓存命中可能比持续扩大上下文更经济。

判断。 应用优先级高，先复现“连续命中、Chunk 重排、中间新增片段、前文强依赖、完全未命中”五类输入。分别记录精确命中 Token、重算 Token、存储读取、TTFT、后续输出质量与 TPOT。不要把 Chunk 命中率直接当作无损复用率，也不要假定插件与所有新版 vLLM 无条件兼容。本次未完整取得附录与全部实验配置，最高收益按作者范围引用。

事件｜2026-11-04。 NanoKV v1 于 11:40:45 UTC 提交；EchoKV v1 于 03:52:59 UTC 提交。本次核验到摘要和版本元数据，尚未形成完整实验表 / 实现审计，列为论文观察项。S26、S27

技术解读。

  • NanoKV： 面向自回归视频生成，在冻结 Backbone 下拟合编码 / 解码组件，以 Cluster Center 表达共享内容，再用低比特残差覆盖 Head / Channel 差异；Key 按输出目标、Value 按重建目标优化。它的对象是视频模型的 KV，不能自动当作 LLM 的通用 KV 压缩。
  • EchoKV： 关注 Query 与保留 Workspace 的反馈耦合：错误裁剪的 KV 产生偏移的未来 Query，进一步强化错误驱逐。通过未来位置 Bootstrap 与早期 Decode Feedback 修复，LAQ 不增加 Forward Pass 数，但重评分仍有计算开销。

性能与数据。 NanoKV 在 HYWorldPlay 报告有效 KV 压缩 26.09×，相对 KVTC 的 PSNR 约 +1dB；Fast 变体压缩 20.53×，端到端相对 KVTC 为 1.15×。26× 内存缩小不能写成 26× Token/s，PSNR 也不是文本任务质量。

EchoKV 摘要覆盖 LongBench 16 类任务，使用 Mistral-7B-v0.2 / Qwen2.5-7B；本次没有可核验的统一 Token/s、压缩比例或所有任务无损结论。

为什么值得关注。 KV 优化有低比特、冗余压缩、选择 / 驱逐和复用等不同路线；压缩存储与选择正确的信息是两个问题。只保持过去的重要度，不一定保持未来 Query 所需的信息。

判断。 NanoKV 适合持续观察视频模型；EchoKV 更适合作为 KV 裁剪失败机制的阅读入口。两者不高于当前可复现的 BitDecoding / DARIC 优先级，取得代码与完整配置后再讨论实际部署。

来源： S26、S27。

本期总结与技术趋势判断

以下为分析。

  1. “少存、少搬、少重算”正在形成互补路线。 BitDecoding 用低比特计算减少 KV 体积与读取，DARIC 复用非连续内容，专家分页把权重容量扩到 Host RAM；NanoKV / EchoKV 则分别研究压缩和保留信息。组合时仍需考虑内存竞争、精度与重算成本，不能简单相乘最高加速比。
  2. 容量收益与单请求延迟可能走向不同方向。 专家分页让模型装得下，却可能因 PCIe 与路由导致 TTFT / TPOT 恶化；FP4 KV 可能提高并发，但 Attention Kernel 的倍率不等于完整 Decode 的倍率；跨 Mac Prefill 也只优化链路的一部分。
  3. 精度问题需要回到具体数值路径。 MLX 的低精度部分和、FP4 的 Scale 下溢、近似 Chunk 复用的跨文依赖，都是可定位、可测试的机制。把质量损失统一解释成“小模型能力不足”会错过真正可修的环节。
  4. Agent 能力是模型与 Harness 的联合结果。 Inkling 的长时实验、工具增强视觉定位、GPT-Live Sideband、Vera Sandbox 和 oMLX Event Loop 都说明最终成功率取决于预算、执行器、状态与回调，不能只看模型榜单。
  5. 开放和可交付性需要独立验证。 Inkling 开放权重仍是计划，HBC 是早期硅片，vLLM 是候选 Tag，oMLX 是开发版，韩国合作是探索。产业关注度不能代替当期可部署事实。
