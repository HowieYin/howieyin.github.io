01｜Claude Fable 5.2：降价与推理状态的严格绑定

事件｜2026-11-09 / 11-12。 Anthropic 发布 Fable 5.2 与同能力、受组织验证限制的 Mythos 5.2；11 月 12 日又增加 Managed Agents 的完整自托管方式。Fable 面向全部客户，Mythos 的开放范围不同；“可使用模型”和“可部署 Agent 服务”是两项能力。S1、S2、S3

技术解读。 Fable 5.2 默认 / 最大上下文 1M，最大输出 128K，始终启用 adaptive thinking，提供 low / medium / high / xhigh / max 五档，默认 high。手动 budget_tokens、禁用思考，以及 tool_choice 强制 any / 指定工具会返回 400。旧 Computer Use 工具版本在部分平台被拒绝，Harness 需按当前文档迁移。

更值得关注的是推理块与前缀绑定：保留后续 thinking block 却修改先前 system、tools 或历史消息，会触发 The block is bound to a different conversation。应保留完整 Assistant Turn 与块顺序，而不能随意剪接历史。临时丢弃推理块的方式会损失已有思考并可能增加输出成本。5.2 的推理块也有模型 / 账户绑定，不能假设旧模型可无缝接续；部分平台会静默丢弃不兼容块。

自托管 Managed Agents 可以把 Agent Loop、会话 / 历史数据库和 Sandbox 放到用户基础设施，模型推理仍由配置的 Provider 提供。cma-server 管理 API、循环与存储，Shell 由轮询的 Worker 执行；持久化需要 PostgreSQL 16+，纯内存模式重启丢失状态。服务 API、模型访问、执行环境三组凭证需要独立管理。自托管不自动意味着对话和工具结果不出网，也不意味着完整服务已经以宽松开源许可证发布。

02｜Gemini 4：Hydrogen、Carbon 与多 Agent Harness

事件｜2026-11-10 / 11-12；部分延续此前事件。 Carbon 此前已有限开放，本期新增付费开发者 / 企业 API 的更广访问，以及 Antigravity /swarm 预览。11 月 12 日 Hydrogen 进入 AI Studio、API 与相关产品；Antigravity 的 Hydrogen / Orchestrator 面向相应付费层级。S4、S5、S6、S7、S8

技术解读。 Hydrogen 面向较低任务成本和更快交互，提供四档思考预算；官方博客分别宣称 1M 输入上下文和最高 1M 输出。这不能自动推导某个 API 端点允许一次请求同时用满两项上限，仍应核对端点组合约束。

Orchestrator 在同一轨迹内双向切换：Carbon 规划 → Hydrogen 编辑 / 测试 → 必要时 Carbon 重新规划。收益来自选模和整个 Harness，并非 Hydrogen 单模型增加了同等能力。/swarm 则使用协调者、并行 Worker 的独立 Git Worktree、对抗式验证与追加式共享消息板。空闲 Agent 可以暂停 Token 消耗，但 VM / 工具等资源不会因此自动免费，多 Agent 也可能更快消耗配额。

03｜Qwen4-Max-Preview：正式预览与推理预算接口

事件｜2026-11-11 10:00，UTC+8；延续此前事件。 上期只有 Qwen4 传闻，本期有阿里云官方 qwen4-max-preview 文档。预览窗口为 11 月 11 日至 11 月 25 日 24:00，结束后退役；仅在 Token Plan 提供，不支持按量付费。本报告不收录 11 月 16 日范围外的正式型号，也不借用其参数或价格。S9

技术解读。 支持文本、图像、视频输入与工具、搜索、JSON Object / Schema；兼容 OpenAI Chat / Responses 和 Anthropic Messages 接口。调用需使用 Token Plan 的专用 Key / Base URL，不能假设普通百炼端点可直接调用。

默认思考 xhigh，支持 low / medium / xhigh；reasoning_effort 与 thinking_budget 互斥。max_tokens / max_completion_tokens 的限制是推理与最终答案共享，旧的“只限制最终回答”配置可能让模型在思考阶段用完预算。Chat Completions 默认 preserve_thinking=true，返回的 reasoning_content 独立于最终 content，不能随意拼接成普通答案。

性能与数据。 文档给出 1M 上下文、最大 393,216 输出 Token，后者包括推理与答案。本期没有核验独立能力 Benchmark、参数量、正式按量单价、TTFT、TPOT 或显存。上期流传的游戏 / 情感等细节没有因预览存在而全部获得证实。

为什么值得关注。 预览让真实多模态 / Agent 任务可测，也暴露了兼容 API 不代表预算语义相同的问题。

判断。 先测试思考保留、限额截断、工具及多模态格式，再做模型比较。将预览到期纳入实验记录；不要依赖限期 ID 构建长期生产服务。

04｜Inkling 2 Small：权重开放与架构专用执行路径

事件｜2026-11-12 / 11-13 至 11-15；延续此前事件。 上期模型已发布但权重关闭，本期 Apache-2.0 权重实际可获取。可见权重上传提交为 11 月 12 日 19:53 UTC，即北京时间 11 月 13 日；vLLM 集成博客日期为 11 月 12 日。llama.cpp 文本 / 视觉转换支持在北京时间 11 月 15 日合并，随后修正图像 begin / end 边界与多余文本 Token。S10、S11、S12、S13、S14

技术解读。 模型为 594B 总参数、17B 激活参数、48 层；40 层 Sliding Window、8 层 Full Attention，窗口 1,024。48 Q Heads / 8 KV Heads 为 6:1 分组，使用学习到的相对位置偏置而非 RoPE；结合短卷积、Attention Residual、Gate 与 Token Sink。384 个专家选 8 个，无共享专家；原生 NVFP4 训练 / 检查点并不等于所有层都用同一精度，前 40 层专家与最后 8 层存在格式差异。

vLLM 针对结构融合 All-Reduce、卷积、Residual、AttnRes 混合与 RMSNorm，减少中间结果读写；序列并行在 Prefill 的局部运算前后使用 Reduce-Scatter / All-Gather。6:1 Head 布局也需要专用 Attention Tile，不能期待通用 Kernel 在所有 GQA 比例下等效。原生 DSpark 为多层 RNN Draft，llama.cpp 本期模型转换支持不包含这套 DSpark。

05｜MiniMax H3 Image：6 步 4K 生成、并行工作点与许可

事件｜2026-11-10 至 11-12。 MiniMax H3 Image 提供实际权重，11 月 10 日可见上传与许可证日期；11 月 12 日 vLLM-Omni 公布 Rubin / Blackwell 等部署性能。开放权重使用自定义 Community License，不是 Apache-2.0 或无条件商业许可。S15、S16、S17

技术解读。 33.1B Dense DiT，50 层、隐藏维度 5,376、56 Heads，使用多模态 3D RoPE；外部 Qwen3-VL 编码器提供表示。VAE 空间下采样与 Latent Patch 组合使 4K / 16MP 对应约 16,384 个目标 Token。蒸馏后固定 6 次网络求值（NFE），guidance=1，不再多跑一套无条件 CFG 分支。

支持多种宽高比、最多 16 张参考图；通常约 4–20MP，最佳点约 16MP。默认最小计算面积为 4MP，某些“1K 输出”实际先计算更大图再缩放，不能视为原生 1K 计算量。默认本地路径要求较详细英文 Prompt；托管 API 会先扩展提示，本地 Prompt Enhancer 可选。比较质量 / 延迟时必须明确是否包含这一阶段。

16｜SinkState：以低秩近似和主机换出来降低循环状态

事件｜2026-11-10。 SinkState 针对混合 Linear Attention 模型的循环状态内存，通过 SVD、活跃 Buffer 和异步 CPU 存储减少 GPU 驻留。S36

技术解读。 保存活跃的约 8 个 Buffer，将较稳定状态低秩压缩并冻结到 CPU，按阈值选择 Rank。循环状态可为 FP32，即使模型权重为 BF16 / NVFP4、Attention KV 为 FP8；所以单看权重精度会漏掉状态成本。截断 SVD 属于近似，不是无损或逐 Token 等价。

性能与数据｜作者实验。 RTX PRO 6000 Blackwell 96GB GDDR7、PCIe 5，配双 Xeon 6515P 与约 252GB 主机内存；4B / 9B BF16、80B / 120B NVFP4 权重等设置。峰值循环状态内存最高缩小 2.6×、平均约 1.9×；Decode 最高 1.58×、平均约 1.25×，不能改写为总 VRAM 同比缩小。

RULER 的 4 项 NIAH / 16K 测试下降不超过约 0.1，Thinking MATH / GPQA / 32K 下降不超过约 0.5；某些结果提升受输出截断减少影响，如 Qwen 9B 截断比例 16.0%→11.4%。这不能证明输出不变，也不能外推所有上下文长度、任务和压缩阈值。

为什么值得关注。 Linear Attention “状态随长度恒定”不代表状态很小，多会话并发仍可能被高精度循环状态限制。

判断。 值得研究状态的秩与精度，但 GPU 收益会转移一部分压力到 CPU、PCIe、主机内存与异步管理；对端侧统一内存系统不能直接照搬 PCIe Offload 数据。复测需分项记总显存、循环状态、KV、主机内存、输出质量和并发。

17｜TKNP：Decode Token Parallelism 的跨节点取舍

事件｜arXiv 2026-11-09 22:01 UTC，北京时间 11-10。 TKNP 在节点内做权重 TP，在节点间按 Token / 请求分配 KV Owner 与当前计算；目标是避免传统跨节点 Attention Partial Result 的通信放大。S37

技术解读。 每层当前 Token 的 Q / K / V Scatter 到 KV Owner，局部 Attention 后 Gather 回活跃根节点；历史 KV 留在 Owner，不是每步搬运整个缓存。不过 Prefill 后仍需初始化 KV 迁移，且 Owner 的 KV 要能装进一个节点。Dual-root 增加第二份权重来提高利用率，不能视作零成本吞吐。

论文的局部 Attention Tensor 流量比例约 1/N，不是整个网络总流量缩成 1/N。短上下文、小 batch 可能因 Scatter / Gather 开销吃亏，Prefix Sharing 在主要测试关闭。

为什么值得关注。 节点内强互连与节点间网络不同，让“权重放哪里、KV 放哪里、当前 Token 去哪里”成为独立设计变量。

判断。 适合研究大模型 Decode 集群；个人端侧相关性较低。复现时把 Prefill 节点、额外权重、副本、KV 初始化、短请求和 Prefix Sharing 算进全系统成本。

18｜One-Sided Expert Parallelism：低 batch 的 NVLink MoE 通信

事件｜arXiv 2026-11-09 20:06 UTC，北京时间 11-10。 新论文设计 NVLink 域内的一侧 MoE 通信，使用确定性地址与融合消费路径降低低 batch Dispatch / Combine 延迟。S38

本期总结与技术趋势判断

以下为综合分析，不是来源直接给出的结论。

第一，推理优化从单算子扩展到状态生命周期。 Rubin 共享 KV 与路由争取热状态，EPD 避免重复多模态预处理，跨版本 KV 尝试绕过缓存失效，SinkState 将循环状态压缩 / 换出。它们减少不同类型的工作，也引入不同风险：容量失稳、协议错误、质量偏移和主机传输压力。只报 Token/s 或局部内存，无法判断完整价值。

第二，交互性、吞吐与总成本必须同图比较。 H3 的 SP / DP 工作点、NIXL 低并发反例、ForeSpark SLO、One-Sided EP 小 batch 优势都说明，单峰值不能代表真实服务。缓存 Token 统计、所有 GPU 分母、额外 Prefill 节点和辅助设备也必须显式列出。

第三，模型与 Harness 正在形成共同协议。 Fable 的推理块绑定、Qwen 的共享推理预算、Gemini 的动态选模 / Swarm，以及 BotPsy 的工具专项训练，都会改变应用代码。更好的模型需要对应的状态、工具、验证与异常恢复，才能转化成更高任务完成率。

第四，开放权重的可用性需要三道实际验证。 Inkling 的聚合显存、H3 的外部编码器 / 许可、BotPsy 的默认思考与后端说明，分别对应资源、使用条款和执行路径。下载得到权重只是起点，不能代替部署、质量与成本评估。

第五，硬件判断继续以交付和实测为准。 Rubin 属 early access，Fractile 商业芯片仍是 2027 计划；融资、互连投资与物理 AI Pilot 表明方向受到投入，但暂不足以得出通用“性能已领先”结论。本期没有独立可比的新增 HBM / DRAM / CXL 产品数据，未用旧路线图填充。

对 Howie 的建议

  1. 优先复测端侧 / 本地路径。 oMLX CUDA Helper 按 8K / 32K / 64K、冷 / 热、单 / 多请求记录 TTFT、有效输出 Token/s、网络字节、内存和故障回退；llama.cpp 按目标 Adreno / Hexagon 设备记录功耗、温控与 Q4 / Q5 质量。不要用 PC 测试替代手机结论。
  2. 建立统一 Agent 状态验收集。 覆盖修改 tools 后接续思考、切换模型、预算耗尽、重复工具、Worker 掉线和多 Agent 冲突；用同任务、同总预算比较 Fable / Hydrogen / Qwen 预览。记最终成功率、P90 完成时间与总费用。
  3. 做 BotPsy 的受限工具基线。 同时测 thinking 开 / 关、BF16 / GGUF，记录参数正确率、工具选择、循环、异常与检索失败；对 Decision Model 则加入概率校准和混淆矩阵，不把 Confidence 当正确率。
  4. 深入读 Rubin、EPD 与缓存崩溃。 用一张分阶段账本区分 Cached / Uncached Input、Output、Encoder、Prefill、Decode、搬运、队列和全 GPU 成本；增加突发结束后的恢复曲线。
  5. 论文复现按收益 / 可用性排序。 先 ForeSpark 的预算 / SLO 和 Prefix Cache 驻留实验，再 SinkState 与跨版本 KV 的质量 / 内存；TKNP / One-Sided EP 适合架构学习，完整集群复现资源要求高。REAL 当前增益小，宜作为损失函数研究。
  6. 谨慎投入高成本模型部署。 Inkling 与 H3 先确认资源 / 许可证，优先使用可控样本验证价值；继续观察正式 Runtime、硬件供货与权重质量，而不是按 headline 采购。
