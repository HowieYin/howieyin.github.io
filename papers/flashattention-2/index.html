Abstract — 一句话、一段话、五个要点

一句话：FA2 保持精确 dense attention 的数学定义，把 softmax 归一化推迟到最后，沿 Query 序列分配更多独立线程块，再让 warp 分别拥有完整的输出行，以减少标量运算和通信。[1]

一段话：FA1 已通过 tiling 和重计算避免把完整 N×N 的 S/P 写到 HBM，但 GPU 的 Tensor Core 仍会等待 softmax、同步和不足的并行任务。FA2 不改变模型参数与 attention pattern，而是重新组织相同运算：保存未归一化的输出分子、只存 logsumexp；前向按 Q 行块并行、后向按 KV 列块并行；线程块内部从 sliced-K 转为 sliced-Q。A100 内核实验报告相对 FA1 1.7–3.0×，端到端训练的收益更小且依赖上下文长度。吞吐数字来自原文，本篇没有运行模型训练或 GPU benchmark。[1]

  1. 算法层：少做 O 的重复除法与缩放，让矩阵乘法占用更多时间；并未消除 rowmax、exp、rowsum。
  2. 线程块层：前向让每个 CTA 拥有一段 Q 和对应 O；更长序列自然产生更多任务，尤其适合小 batch。
  3. warp 层：让不同 warp 拥有不同输出行，避免为了同一 O 合并多个 KV 分片的部分和。
  4. 数值层：“exact”意味着没有稀疏化或近似 attention；浮点运算重排和原子加不承诺 bitwise 一致。
  5. 实验层：73% 是特定 A100 kernel FLOPs 口径，72% 是另一套训练 MFU 口径；Table 1 的端到端增益需逐行计算。

1 Introduction — FA1 已减少 IO，Tensor Core 为何仍没吃满

论文问题。长序列 dense attention 的计算量随 N² 增长。近似、稀疏、低秩路线改变计算图；FA1 选择保留 full attention，通过片上计算和反向重计算减少 HBM 读写。2023 年引言中的 GPT-4 32k、MPT 65k、Claude 100k 是历史背景，不作为今天的能力上限。[1]

新观察。FA1 的内核已经比标准 attention 快，但矩阵乘法吞吐远低于设备峰值。引言写前向约 30–50%、后向约 25–35%；摘要的 25–40% 是概括范围，不能混作同一个实验配置。作者把原因归于 non-matmul 工作、线程块并行不足和 warp 间共享内存通信。[1]

重构理解。相同 FLOPs 不代表相同时间。对 A100，低精度 Tensor Core GEMM 和 FP32 标量算术的峰值能力差异很大。即使 exp/归一化只占少量逻辑运算，也可能成为无法被 GEMM 隐藏的串行部分。一个内核还会受任务数量、寄存器、shared memory、同步和数据依赖共同制约。

层次 FA2 改变什么 为什么有用 没有改变什么
算法状态 保存分子 U，最后除以 ℓ；保存 L 减少重复 output normalization 与统计量保存 dense softmax attention

2 Background — 运算、内存与旧版算法

2.1 Hardware characteristics — 三种通信距离

A100 的例子是 40–80 GB HBM、约 1.5–2.0 TB/s 带宽、108 个 SM，每 SM 192 KB 的片上 SRAM 资源池；原文使用约 19 TB/s 的 SRAM 带宽估计。192 KB 不能理解为每个 CTA 都可以不受配置限制地申请 192 KB shared memory。寄存器分配、shared/L1 配置和单块上限共同决定实际驻留。[1]

一个 warp 为 32 threads。warp 内可使用 shuffle；warp 间通常通过 shared memory 加同步通信；不同 CTA 之间无法靠普通块内 barrier 协调，需要原子、额外内核或其他全局机制。图中的“worker”是 CTA，不是一个 thread；把这三层混淆就会误读 sliced-Q 的作用。

2.3.2 FlashAttention backward — 多做一次 GEMM，少保存 N²

前向不保存 P，反向重新算 QKᵀ 和 exp(S−L)。它增加重计算，但避免在 HBM 保存和加载 N×N 概率。反向依次涉及 QKᵀ、PᵀdO、dOVᵀ、dSK、dSᵀQ 五个 GEMM，依赖和片上状态比前向两个 GEMM 更复杂。[1]

“线性内存”指随 N 线性增长的全局输入/输出和保存状态，不代表计算量线性，也不代表每个 CTA 的 shared memory 常数为零。FA2 的存储改进不能直接推导为 KV cache 压缩。

3.2 Parallelism — 切行让前向独立，切列让后向局部累加

5 Discussion and Future Directions — 历史承诺及其适用条件

作者展望 H100/TMA、新 Tensor Core、FP8、AMD、编译器支持，以及与 local/dilated/block-sparse attention 组合。这些是 v1 的后续方向。FA2 对 dense attention 的精确性不自动适用于任意近似模式；稀疏模式若改变可见 KV，就必须重新说明模型定义与质量。[1]

“2× faster allows 16k context for the same price as 8k”需要固定总训练 tokens 等条件：attention 单条样本随 N² 增长，固定 token 数时 attention 成本约随 N 增长；N 翻倍与 attention kernel 2× 加速可互抵。若固定 sequences 数，则工作量约 4×，或若训练其他模块/通信变化明显，就不能直接说价格相同。

论文没有改变损失函数、参数量和训练数据；“Training pipeline”是在相同 Transformer 的 attention 子图替换内核。推理 prefill 与训练前向共享 dense Q×KV 结构，可从 FA2 的并行分工受益；单 token decode 的 Q 只有一行，不能复用长 Q 序列的同等并行供给。

7 Engineering Interpretation — 从 per-op 迁移到完整调用链

真正可迁移的思想是 结果所有权减少通信。FA1 先解决全局 HBM 中间结果，FA2 继续解决块内输出部分和与全局任务供给。迁移到不同硬件时，先识别最慢路径，再决定 tiling 和并行轴；NPU/HTP 的 SRAM、DMA、矩阵单元和执行调度与 CUDA 不同，不能照搬“4 warps”或 A100 吞吐。

阶段 Q/KV 结构 FA2 可能改善 还需审计的全链路成本
Training Q/KV 都长，反向重计算 前向并行、output 归约、HBM 保存 QKV/FFN GEMM、通信、optimizer、activation checkpoint
Prefill / TTFT 多 Query 与完整 prompt KV 长 Q 块供给、少 S/P 中间写回 tokenizer、H2D、投影/RoPE、logits、首 token 采样
Decode / TPOT 常为一条 Query、历史 KV 长 具体实现的 KV 流式读取 KV 带宽、权重读取、batch、launch、split-KV 归约
端侧 VLM 图像编码与长图文 prompt 仅适配后的 attention 子图 vision encoder、跨设备同步、量化转换、内存峰值

在 prefill/decode 分离的系统里，attention scale、RoPE、mask、KV layout、logsumexp 精度和 logits/采样路径都应统一核对。FA2 改变求和顺序产生的小误差，不应掩盖 KV 索引或掩码方向导致的逻辑错误。可先在 float64 小样本校验，再对真实 dtype 比较分数、输出和 dQ/dK/dV，最后测稳态链路。

1. 结论与证据边界

FlashAttention-2（FA2）的核心贡献是减少非矩阵乘运算、增加序列维度上的 CTA 并行度、改善 warp 内工作分配，而不是首次发明 online softmax，也不是把稠密 attention 的计算复杂度变为线性。其 2023 年的性能结论必须限定到当年的 A100/H100、精度、形状与实现版本；不能直接推广成 2026 年的统一 SOTA。R1R2R5

FA2 已正式收录于 ICLR 2024，官方 proceedings 的标题与作者均对应 Tri Dao 的 FA2。2023-07-17 是 arXiv v1 首次提交日，2024 是会议收录年份；不能把这两个日期混为一谈。这里没有核验 poster/oral 类别，不作该项断言；算法逐式核对和历史 benchmark 仍限定 v1，不声称会议版与 v1 逐字相同。R26R1

FA3 和 FA4 均有可核实的一手论文。FA3 是 Hopper 异步流水线与低精度扩展；FA4 于 2026-03-05 正式发布论文与作者博客，重点适配 Blackwell 的非对称硬件扩张。2026 年 9 月还出现 Meta 的 MXFP8 前后向扩展以及独立的 FP4 FA4 研究，不能将这些不同代码与精度契约合并为一个“官方 FA4 全精度支持”结论。R8R10R11R21R23

截至截止日，官方仓库可核实的最新稳定 FA2 release 是 v2.8.3.post2（2026-10-13），最新列出的 FA4 预发布 release 是 fa4-v4.0.0.beta37（2026-10-28）。releases/latest 返回稳定 FA2，不代表 FA4 没有新版本。主线核验固定在 98c1cee0ed59307833841cdbf567fe336ceec13a，提交时间为 2026-10-24；仓库 pushed_at 为 2026-10-29，二者不是同一时间字段。R12R14R15

3. 同期 xFormers、Triton 与可比性

FA2 v1 §4.1 的基线包括原始 FA1、xFormers 的 CUTLASS memory-efficient attention、Triton 的 FlashAttention 实现及标准 PyTorch attention。xFormers 是可分派到多种内核的工具库，Triton 是语言/编译器及相应内核实现；二者不是与 FA2 完全互斥的数学 attention 算法。R1R6R7

2023 年作者博客注明 Triton 使用 2023-07-14 的最新开发版。v1 论文的更细分结论是 FA2 相对当时 Triton forward 约 1.3–1.5 倍、backward 约 2 倍；博客“约 2 倍”概括不可替代这组前后向差异。（作者报告，未独立复测）R1R5

2026-10-29 读取的 Triton 官方 Fused Attention 教程已直接声明实现 FA2，并包含 tensor descriptors、Hopper/Blackwell 判断及 warp specialization。当前 xFormers 源码 xformers/ops/fmha/dispatch.py 已转导入 mslk.attention.fmha.dispatch；仅凭旧图或旧 cutlass 标签推断当前实际执行内核不可靠。这里不将教程页面中硬件上下文不完整的 TFLOPS 表作为跨库排名。R6R7

4. FA3、FA4 与 2026 年低精度后续

4.1 FA3：Hopper 异步流水线

FA3 首次提交于 2024-07-11，v2 为 2024-07-12。它利用 WGMMA、TMA、producer/consumer warp specialization、matmul 与 softmax 的跨/内 warpgroup 重叠；FP8 路线另加入 block quantization 和 incoherent processing。R8R9

原论文/作者博客报告 H100 FP16 相对 FA2 约 1.5–2.0 倍、最高 740 TFLOPs/s（75%），FP8 接近 1.2 PFLOPs/s。FP8 误差“降低 2.6 倍”是相对指定 baseline FP8 attention 的实验，不是相对 FP16/BF16/FP64，也不是下游任务无损保证；博客明确包含带 outlier 的合成输入实验。（作者报告，未独立复测）R8R9

4.2 FA4：Blackwell 非 matmul 资源成为关键限制

FA4 的新重点是 TMEM、异步 tcgen05.mma、新 forward/backward 流水线、部分指数多项式模拟与条件重缩放、2-CTA backward 降低 shared-memory traffic 和 dQ atomic，以及 causal/varlen 调度。实现使用 Python 内嵌 CuTe-DSL，不能称为“仅升级 Tensor Core GEMM”。R10R11

主文 §5 报 B200 BF16，序列 1K 到 32K、总 tokens=32K，head dim=64/128 或特殊 (192,128) 配置，最高 1613 TFLOPs/s，相对 cuDNN 9.13 最多 1.3 倍、相对当时 Triton 最多 2.7 倍。作者博客则写 1605 TFLOPs/s。应保留出处差异，不能将一个值“修正”为另一值。（作者报告，未独立复测）（来源存在差异）R10R11

更重要的反证是论文图 4 图注及附录说明：新版 cuDNN 已吸收 FA4 技巧，性能接近 FA4，附录列出 cuDNN 9.19.1.2。因此“FA4 截至 2026 年领先最新 cuDNN 1.3 倍”不是原文支持的结论。R10 2024 年 NVIDIA cuDNN 9 博客也有自身融合 SDPA 与低精度实现，提醒比较的是不同版本的具体内核，而不是“cuDNN 对 FlashAttention 思想”。R20

原文还有必须披露的内部不一致：

  • §5 与图注明 B200，附录 A.1 却写 B100 180GB SXM6 (1000W)；同一附录写 (March 2025)，而 arXiv v1 是 2026-03-05。HTML 与公开 TeX 均如此，疑似笔误但没有作者勘误，不擅自统一。（来源存在差异）R10
  • 附录列 CUDA 13.1、FA 2.8.3、Triton 3.6、PyTorch 2.10.0、CuTe-DSL 4.4.1；这些是原文所列环境，不是本次复现实验环境。R10
  • 论文 §5.2 的 deterministic backward 最高约为指定 1-CTA nondeterministic 基线的 75%；作者博客写约 85–90% nondeterministic throughput。参照内核/设置未完全对齐，不合并为一个确定比例。（来源存在差异）R10R11

FA4 的“exact attention”也需细分：不做稀疏截断或改变目标 attention 公式，不代表指数实现与 FP32/FP64 完全一致。原论文表 2 的三次指数多项式相对 FP64 最大 FP32 相对误差约 8.77×10−58.77\times10^{-5}，大于硬件 MUFU；round 到 BF16 后两者误差接近。该实验只是指数近似在 4M 个 [0,1) 输入上的局部误差分析，不是完整模型/训练误差定理。（作者报告，未独立复测）R10

4.3 2026-09：Meta MXFP8 与独立 FP4 研究

Meta MXFP8 扩展。 PyTorch 官方博客发表于 2026-09-16、页面另显示更新日 2026-09-23，报告 FA4 fork 的 MXFP8 forward/backward、融合 quantization producer 和 jagged 模块。GB300 LLM 形状前向最高 2.85 PF/s；但 cuDNN 9.24 MX8 为 2.82 PF/s，属于接近而非普遍领先。内部 jagged 形状 FA4 MX8 为 2.54 PF/s、cuDNN MX8 为 2.64 PF/s，后者更快。（作者报告，未独立复测）R21

博客主动排除了一个不合格的横向对照：cuDNN 9.24 + Frontend 1.26 的 MXFP8 backward 在 nonuniform E8M0 V scales 下 dQ/dK 不匹配 reference；其 1.76 PF/s 只能算 performance-only，不能算通过精度核验的速度排名。Meta 路线还可能返回量化 dK/dV，与 BF16 gradient 返回契约不同。对应模块端到端前后向在 4K KV 时约 1.00 倍、16K 时约 1.30 倍，不能将内核 1.6 倍推广到模块或服务。R21

其可核实代码在 facebookresearch/ads_model_kernel_library/lp_fa4，不是 Dao-AILab 主线的通用 FP8 backward。2026-10-29 README 固定快照 2e8689e43325fe215f79802467c0d8a0e592bf88 声明 unpublished release candidate；初始 MXFP8 API 限定 noncausal、head dim 128、MHA，含 dense/packed varlen/shared-Q。README 的 kernel benchmark 预先量化再计时，与博客的融合模块边界也不同。R22

FP4 独立研究。 Robert Hu 的 Hardware-Aware FP4 FlashAttention-4 首次提交于 2026-09-03，研究 noncausal Direct-P 和另行设计的 causal training 路线。论文自报有利形状 GB200 forward 最高约 2.13 倍 BF16、单 GPU 8B update 最高约 1.14 倍；其“full FP4”只指 Q/K/P/V attention operands，不是全 Transformer 纯 FP4。尤其是作者明确报告：所测试的 MXFP4 P/V 分布式训练轨迹均发散，保留的训练配置使用 FP8 P/V。（作者报告，未独立复测）R23

上述后续的存在已经核实，但性能与稳定性没有三方独立复现，不能升级为通用推荐或统一 SOTA。本次对作者站点、官方仓库与 FlashAttention-5 的 2026 年检索未发现可核实的官方 FA5 论文/发布；这是有限检索中的未发现，不是不存在的证明。

FA4 主线架构与形状分派 interface 还接受 CC 8.x/9.x/10.x/11.x/12.x，含独立 SM80/SM120 等路径 不能把“源码存在路径”当所有卡/形状已复现。SM90 对齐形状 8–256；SM100/110 通用范围 8–128，另有 (256,256) 等特殊配置；不是任意 hd≤256 的统一矩阵。R13
Meta LP-FA4 release candidate README 测试依赖：Linux、Python 3.12、SM10x、CUDA 13、PyTorch 2.13.0、DSL 4.6.1、Quack 0.6.2 显式 MXFP8 前后向 API，初始 noncausal MHA hd128；可返回量化 dK/dV；这些是本次读取 README 的测试依赖，不是保证已广泛可安装的稳定栈。R22

主线 README 对 Linux 是正式要求；Windows 只写可能可用且需要更多测试。没有据此证明 Mac/Metal、CPU、所有 Blackwell 消费级卡获得同一 FA2/FA3/FA4 优化内核。R12R13

5.1 必须随版本记录的正确性变化

  1. FA2 v2.8.3.post2 修复 backward dq_accum int32 offset 溢出：当 batch * round128(seqlen_q) * nheads * headdim > 2^31 时旧代码可能非法访问或 NaN gradient。该版本是维护修复，不是新的内核功能发布。R14
  2. FA4 beta37 列出未使用 KV cache 值的 NaN 污染、ragged K/V TMA bounds、2-CTA CLC work-tile coordinates 等修复。不能把旧版本偶发错误等价于数学 attention 算法错误，也不能凭新版说明宣称所有边界均已消除。R15
  3. FA2 自 v2.1 起，seqlen_q != seqlen_k 的 causal mask 改为 右下对齐；PyTorch SDPA 文档的非方阵 is_causal 是 左上对齐。decode/cross-attention 的 API 替换必须显式核验 mask 语义，不能只比较 dtype 和形状。R12R17
  4. “Exact”不意味着 bitwise 相等。官方测试以 output/gradient 相对 reference 的误差容忍为准，README 写最大误差不超过 PyTorch baseline 误差约两倍；它是测试标准，不是所有可能输入的数学误差界。FP8/FP4 的量化、缩放、梯度格式与确定性还必须另验。R12R17

PyTorch SDPA 会按输入条件选择 fused 或 math 等后端；调用 SDPA、安装 flash-attn、以及真正执行某版本 FA 内核不是同一事实。应使用 sdpa_kernel 控制、实际分派日志和 profiler 证实路径；更高精度 math backend、dropout、mask 等限制也会改变结果。R17

6. Prefill、Decode、TTFT 与 TPOT

概念 计算 / 指标定义 对 FA2 结论的影响
Prefill 通常并行处理 prompt 多个 query tokens，生成各层 KV；长 prompt 常有较高算术强度 接近训练 forward 的大 Q 形状，但没有 backward；不能拿 forward+backward 倍率替代 prefill 倍率。R16R19
Decode 常规自回归每步 query 长度约 1，读取不断增长的 KV cache 小 Q、少 batch/head 时 CTA 并行不足，常受 KV/HBM 或固定开销限制；需要 split-KV、合并、paged 布局与服务调度。R16R19R24
TTFT 请求发出到首个输出 token 的时间 包含排队、传输、tokenization/调度、prefill 与首 token 输出等；不是纯 attention 或纯 prefill kernel 时间。R18
TPOT 对一个输出 tokens>1 的请求，(Tlast−Tfirst)/(nout−1)(T_{\mathrm{last}}-T_{\mathrm{first}})/(n_{\mathrm{out}}-1) 排除 TTFT，主要反映首 token 后生成间隔；需报告输出长度与服务计时边界。R18
ITL 相邻输出 token 完成之间的间隔 单请求 TPOT 是 ITL 平均；跨请求 mean TPOT 通常按请求等权，mean ITL 按 token 间隔加权，二者可不同。R18

“Prefill 总是 compute-bound、decode 总是 memory-bound”过于绝对。2026-07-31 NVIDIA 原文指出短增量 prompt + 长 prefix cache 的 prefill 可接近 decode；speculative decoding 多 query 验证会增加算术强度，可能向 compute-bound 移动。FA4 又显示即使长 Q 内核，SFU 和 shared-memory traffic 也可能是瓶颈，而不是 Tensor Core FLOPs。R19R10

Flash-Decoding 于 2023-10-12 的作者/团队博客提出沿 KV 长度分片并行，再以每片 LSE 合并；它自 FA package v2.2 与 xFormers v0.0.22 提供。因此“FA2 完全不能优化 decode”不准确；准确说法是 FA2 v1 的 forward Q 分块并行策略不能单凭训练结果保证小 Q decode 加速，后续版本另有 decode 路线。博客的“batch 1 少于 1% GPU”示意不能忽略 heads 维后照搬到任意 MHA。R16R12

在线性能还须控制请求到达率、并发、prefix cache 命中、chunked prefill、KV dtype/布局、输出长度、调度与通信，并报告 p50/p95/p99 和 goodput。vLLM 文档提供 TTFT/TPOT/ITL 百分位与 SLO goodput 参数；这些是指标配置，不是 FA2 改善指标的实测证据。R25

8. 性能结论的使用边界

稠密、保持目标公式、同 dtype 不足以完成公平比较。至少应对齐 GPU 型号/功耗/时钟、软件快照、batch 与 Q/K 长度、Q/KV heads、head dim、causal/varlen/paged/dropout、输入与返回梯度 dtype、确定性、量化和 layout conversion 是否计时、编译/warmup、kernel/model/server 计时边界以及误差标准。R1R10R21R22

短 Q/短序列可能被 launch、调度与最终 reduction 开销主导；长 Q 与宽 head 又可能遇到寄存器、shared memory、TMEM 与 SFU 限制。稀疏/低比特工作可以是有价值的后续，但改变了计算/精度契约，不应与 BF16 稠密 exact attention 无条件并列排名。R1R10R19R23

本次 （尚无独立验证）：没有跨作者独立重测 FA4 当前 release、没有 GPU 支持矩阵实测、没有覆盖全部 2026 年 attention 文献，未将有限检索未发现 FA5 写成不存在。原文中的 synthetic benchmark 是被引用的实验方法，不是本调研生成的模拟数据；不使用这类局部实验替代真实生产普适结论。

9 My Takeaways — 优势、代价与未解问题

优势。FA2 在保持模型定义和精确 attention 的前提下优化内核执行，迁移成本比改模型 attention pattern 小。算法状态、CTA 轴和 warp 所有权三个层次连贯；作者明确承认 Triton 先行贡献，原始图和开源实现为复核提供入口。

代价。大 tile 和更多片上状态可能降低 occupancy；后向 dQ 原子归约存在通信和确定性成本；Q-block 并行增加不同 CTA 对 KV 的访问，cache/复用路径会影响实际 IO。MFU 数字依赖 FLOPs 口径，kernel speedup 不能直接替代训练或业务收益。

正确性评价。设计的不变量容易证明；v1 文本与伪代码存在可确证错误，因此技术报告和正确实现需分开评价。数学自检支持校正后的算法，不替原始性能实验提供独立实测背书。

扩展性评价。长 Q、适当 head dimension 和 Tensor Core GPU 是强场景；q_len=1、极小 tile、跨设备、低精度/全 mask 等场景需要额外设计。本文没有一种统一可比的“所有场景最快 attention”结果。

尚待回答。三个改进各自节省多少时间？反向原子与确定性策略在不同形状如何切换？哪个 block 参数改变了 GEMM 与标量流水的临界点？prefill 的收益是否被模型其他算子和跨设备调用淹没？这些比继续引用一个整体“2×”更能指导落地。

下一步实现方向。用 profiler 按真实调用顺序检查等待、内存拷贝、kernel launch 和每个 GEMM/softmax/归约，再选择内核。面对端侧部署，保留 thin JNI/native 主链路的原则，把容量估算与真实物理峰值分开，把数学对齐与稳态 TTFT/TPOT 分开验收。
