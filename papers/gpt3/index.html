GPT-3：参数规模如何改变上下文学习

Language Models are Few-Shot Learners · 2005.14165v4 · 全文与附录精读

GPT-3 的贡献是把同一个预训练语言模型变成一种可用文本示例配置的任务接口。它展示了规模增长带来的广泛迁移能力，也留下了明确的阅读理解、自然语言推理、可靠性与成本缺口。

摘要与全局理解

一句话。 把模型从 125M 扩大到 175B，并在相同的 300B token 训练量上观察：测试时不更新权重，仅在上下文中给任务描述与示例，许多任务的效果会随规模改善。

一段话。 传统 NLP 为每个任务收集标签、微调参数。GPT-3 将任务适配放进自回归语言模型的输入序列：模型依次看到指令、若干输入输出对和待回答输入，再预测答案。175B 模型在 LAMBADA 达到 86.4% accuracy，TriviaQA 达到 71.2%，但 SuperGLUE 只有 71.8，DROP 只有 36.5 F1，ANLI 仍接近弱基线。论文证明这种接口具有广泛价值，尚未证明它掌握了普遍可靠的推理算法。

五个关键点：

  1. 不更新参数不等于没有监督信息。 Few-shot 示例包含标签；模型还见过海量预训练文本，研究者也设计任务模板和选择 K。
  2. 预训练与测试适配是两条链路。 前者有梯度和 Adam，后者只有 forward；“inner loop”不能读成梯度下降。
  3. 大模型受益更多，但不是每个任务、每次增加示例都更好。 ARC、WiC、阅读理解提供反例。
  4. 污染分析有用，但不能识别记忆对分数的因果贡献。 Clean subset 与完整测试集的难度可能不同。
  5. 示例有硬件成本。 2048 token 窗口限制 K，175B 权重与 KV 容量使纯 forward 的“适配便宜”仍伴随昂贵推理。

§1 Introduction：从任务模型到文本配置

问题、已有方法与核心观察

任务专用系统需要大量标注和微调；当任务分布变化时，要重复收集数据和调参。GPT-2 已展示 zero-shot 迁移，但能力不稳定。本文问的是：继续扩大自回归模型，能否让人用自然语言与少量示例更稳定地指定新任务？

这里的 “meta-learning” 是对行为的描述。预训练文本可能包含可重复子任务，模型学习其统计结构，随后利用上下文辨认任务。Figure 1.1 并不是作者逐条展示训练集里的真实元学习样本；它是概念示意。

读图。 上方外循环是语言模型预训练，下方内循环是同一序列内部的条件预测。箭头沿文本顺序推进，参数在测试阶段保持不变。不能凭这张概念图断言模型实现了 MAML。

读图。 横轴是上下文示例数量，纵轴是删除单词中随机插入符号的准确率；分别比较有 / 无自然语言任务描述。较大模型更能利用示例。受控任务支持“规模促进上下文适配”，不能直接推广到所有真实任务。

读图。 横轴模型规模，纵轴 42 个以 accuracy 计分的基准的聚合表现。Few-shot 曲线随规模提升更快。均值掩盖了任务之间的巨大差异；BLEU、F1、困惑度等也不能无条件揉进这条曲线。

因果链与可证实的贡献

观察到的是“给更大模型相同类型的任务文本，更多任务分数改善”。同时变化的包括模型参数、训练 FLOPs 和可用表达能力；它不是独立隔离每一因素的因果实验。175B 的新价值是广度与可配置性，不是一个新的 Attention 算子。

§2 Approach：方法重建与模型配置

§2.0 评测接口：zero / one / few-shot

读图。 Fine-tuning 分支更新模型；其余三种分支改变输入。Zero-shot 仍可包含明确指令；one-shot 给一对演示；few-shot 通常给数十对。示例文本不是模型永久记住的新权重。

输入是 token 序列，输出是答案的条件概率或生成文本。把示例集合记作 D，把任务输入记作 x，答案记作 y：

AGENT-CREATED DERIVATION · ICLPθ(y∣D,x)=∏t=1|y|Pθ(yt∣D,x,y<t),θeval=θpretrained
LaTeX sourceP_\theta(y\mid D,x)=\prod_{t=1}^{|y|}P_\theta(y_t\mid D,x,y_{<t}),\quad \theta_{\mathrm{eval}}=\theta_{\mathrm{pretrained}}

符号与形状。 θ 是固定权重；D 和 x 拼进一个 token 轴；每一步输出词表大小 V 的 logits。乘积是整个答案的条件概率，不是另一个分类器的概率。即使模型可以从示例推断规则，答案仍由同一个 next-token 目标产生。

§2.1 架构、张量与参数

沿用 GPT-2 的 decoder-only Transformer：pre-LayerNorm、残差、learned absolute position embedding、byte-level BPE。作者交替使用 dense 与 locally banded sparse attention。Context 为 2048；不是现代长上下文模型。

读表。 八个规模共享 300B 训练 token，层数、宽度、头数、批量与学习率不同。175B：96 层、d=12288、96 个头、每头 128，MLP 宽度 49152，目标 batch 3.2M token。小模型与大模型不是只改一个数字。

原文一致性审计。 13B 行 d_model 写作 5140，而 40×128=5120；本文保留原值并标注差异。1.3B 行 d_model=2048，24×128=3072，并不自动构成错误：Attention 的投影总宽度可以与 residual 宽度不同。没有公开实际配置，不能擅自把两行“修正”为猜测值。

§2.2 数据混合与质量

读表。 Common Crawl 提供最大容量，WebText2、Books1/2、Wikipedia 被不同程度上采样。可用数据约 499B token，但训练采样 300B；小而高质量的源可以重复，大源不必遍历。

§2.3 训练链路

模型在 Microsoft 的 V100 集群训练，使用跨模型维度与跨层的并行切分。论文没有给出足够 GPU 数、wall-clock、网络与 kernel 信息来复现实测吞吐。

AGENT-CREATED DERIVATION · LOSSL(θ)=−1T∑t=1TlogPθ(xt∣x<t)
LaTeX source\mathcal L(\theta)=-\frac1T\sum_{t=1}^{T}\log P_\theta(x_t\mid x_{<t})

目标。 T 个位置预测下一 token，log-softmax 作用于 V 类，最后对位置求均值得到标量 loss。所有 token 统一赋权；目标本身不验证回答的真实性或任务执行正确性。

Adam β₁=.9、β₂=.95、ε=10⁻⁸，梯度 clip=1、weight decay=.1；375M token 学习率 warmup，随后 260B token 余弦衰减到峰值的 10%，之后保持底值。Batch 从 32K token 在前 4–12B token 增到目标 batch。将文档装满 2048 token，用 EOT 分隔；没有文档间独立 attention mask，后文能注意到前文。

§2.4 评测：模板也是方法的一部分

K 通常在 10–100 之间，受 2048 context 限制，有 dev 时在那里选 K。每个 query 随机抽选 conditioning 示例；同一个模板可以跨测试样本复用，具体示例不一定相同。LAMBADA / StoryCloze 用 dev 示例评 test，原版 WSC 会从同一数据集取示例；要精确复现仍需审计排除当前 query 的实现。

多选题多用答案 token 的平均 log likelihood。ARC、OpenBookQA、RACE 用下面的背景似然校准：

AGENT-CREATED DERIVATION · SCORESavg(a,c)=1|a|∑tlogPθ(at∣c,a<t),Sratio=logPθ(a∣c)−logPθ(a∣Answer:)
LaTeX sourceS_{\mathrm{avg}}(a,c)=\frac1{|a|}\sum_t\log P_\theta(a_t\mid c,a_{<t}),\quad S_{\mathrm{ratio}}=\log P_\theta(a\mid c)-\log P_\theta(a\mid \mathrm{Answer:})

解释。 普通 score 用长度归一化减轻短答案偏好；ratio 的对数是“给问题后的 log 概率”减去“通用 Answer: 后的 log 概率”，压低只因高频而讨巧的答案。其分母不是外部知识检索。自由生成任务使用 beam=4、length penalty=.6；新闻与诗歌等采样任务有不同设置。

§3 Results：逐项读实验

§3.0 训练 loss 与规模

读图。 计算量增加，held-out cross-entropy loss 大体平滑下降，延续早期 scaling law 两个数量级。该图计算与参数量排除 embedding。平滑 LM loss 与某项任务突然改善可以同时存在；不同指标没有一一线性映射。

§3.1 Language Modeling、Cloze 与 Completion

PTB perplexity 从此前的 35.8 降到 20.5，本文算得相对下降 42.74%。PPL 越低越好；作者刻意避开来自 Wikipedia 等高重叠来源的常见 LM 基准，因此这不是覆盖所有语言建模数据集的结论。

LAMBADA。 Few-shot accuracy=86.4，相比原 baseline 68.0 提升 18.4 个百分点，相对提升约 27.06%；相比 GPT-3 zero-shot 76.2 提升 10.2pp。Figure caption 的 “18%” 不应不加解释地当成相对百分比。Zero-shot / few-shot 使用不同格式，one/few-shot 用 blank completion，模板与 K 的作用混在一起。One-shot 72.5 低于 zero-shot 也说明示例不是稳定加分项。

其他 completion。 HellaSwag 79.3 vs 85.6、StoryCloze 87.7 vs 91.8，仍低于专门微调 baseline。LAMBADA 的亮点不能代表这整个任务类均达到当时 SOTA。

§3.2 Closed-book QA

读图与结果。 TriviaQA 随规模增长明显，few-shot 71.2，高于表中的 RAG 68.0；NQ 29.9 仍低于 T5+SSM 36.6 / RAG 44.5，WebQuestions 41.5 仍低于表中 44.7。Closed-book 无显式检索，但拥有大规模预训练；open-domain RAG 的检索语料与微调监督不同。表 H.1 对 WebQs baseline 列出 45.5，正文表列出 44.7，应保留各自口径。

知识存储与检索接口是两回事：正确回答可能来自记忆，也可能来自模式泛化；这些准确率无法单独区分二者，更不能保证事实更新。

§3.3 Translation

读图。 六个语言方向的 few-shot BLEU 随容量总体改善，译入英语通常强于译出英语。En→Fr=32.6、Fr→En=39.2、En→De=29.7、De→En=40.6、En→Ro=21.0、Ro→En=39.5。

§3.5 Commonsense Reasoning

§3.6 Reading Comprehension

CoQA few-shot 85.0 F1，接近但未达到 90.7；DROP 36.5 vs 89.1，SQuAD 69.8 vs 93.0，QuAC 44.3，RACE-h/m 46.8/58.1。QuAC one-shot 正文 43.3 与 H.1 43.4 有差异。

读图。 CoQA F1 随规模总体增长，大模型从 few-shot 获得更多收益。85 F1 是对话阅读理解的强项，不代表 DROP 或 RACE 也具备同等水平。

§3.9 Synthetic and Qualitative Tasks

§5 Limitations

作者承认长文一致性、重复、常识矛盾与推理薄弱；模型缺乏 grounded interaction，next-token loss 对所有 token 赋相同权重，训练样本效率低，机制难解释，推理规模昂贵。建议研究双向架构、目标改善及 distillation，但并未实验确认这些能消除所有问题。

本文判断。 应把“任务文本可配置”与“任务结果可验证”分开。Few-shot 减少每任务 optimizer 工程，却把风险迁移到模板、示例选择、分词、上下文容量与输出验证。对 OCR / 端侧 VLM 系统，本文只是文本 LM，不能从它的结果直接推导视觉 encoder 或 OCR 量化可行性。

相关工作串起 dense 参数扩展、MoE 条件容量、adaptive computation、迁移 / meta-learning 与文本生成。规模是一条进步路径，但 MoE 的总参数与活跃参数不能混算，adaptive depth 也不等同于本文的固定 decoder。

def answer(model, tokenizer, demos, query, mode):
prompt = render_task_template(demos, query)
ids = tokenizer(prompt)
assert len(ids) + reserved_answer_tokens <= 2048
# Evaluation changes context; no optimizer step.
logits, kv = model.prefill(ids, use_cache=True)
if mode == "multiple_choice":
return score_candidates(model, kv,
length_normalize=True,
background_calibrate=task_needs_ratio)
output = []
for _ in range(reserved_answer_tokens):
token = choose_token(logits, task_decoding_config)
output.append(token)
logits, kv = model.decode(token, kv)
if token == stop_token:
break
return tokenizer.decode(output)

输入 / 输出 /成本。 Prefill 输入 [B,T]、输出最后位置 [B,V] 和逐层 KV；decode 每步输入 [B,1]，KV 随历史长度增长。Multiple-choice 的每个 candidate 必须从同一未被其他 candidate 改写的 prefix KV 起步，候选概率需累计多个 token，不能只看答案第一个 token；背景校准还要单独计算 denominator。

Critique 与个人判断

最强证据。 广泛任务、八个规模与三种 setting 的矩阵，使少样本文本接口从个别演示成为系统研究对象；保留全部负结果是这篇论文的重要价值。

最弱的推论。 把 task performance 解释为通用“学习算法”、把污染 clean/full 差值解释为记忆贡献、把 52% 人类辨认率解释为生成质量。三者分别缺机制干预、随机因果设计和事实正确性指标。

工程启示。 任务适配由 optimizer 路径迁到 prompt 路径，上层接口看起来简单，系统必须承担模板版本、token 预算、KV 复用、校准、数值一致性与输出验证。量化时应先定位敏感层与导出精度损耗，再讨论模型能力。无需为了验证假设先迁移应用业务逻辑。
