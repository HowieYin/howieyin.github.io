改动像素的方向，为什么比改动幅度更容易骗过分类器？

结论：对这个真实数字分类实验，同等 L∞ 像素预算下，沿损失梯度符号修改像素，比随机选择符号更容易造成误分类。小幅改动是否危险，取决于方向、决策边界与输入坐标；测试集准确率高，不等于附近每一种输入扰动都安全。

类型：视觉趣味实验 / 模型行为。发布与实验：2026-11-23。使用真实 scikit-learn digits、独立训练的三个 MLP、CPU 自动微分；没有调用 LLM 或 Attention，没有攻击外部服务。8×8 教学数据上的结果不是 ImageNet、OCR、真实相机或物理攻击效果，也不声称扰动不可被人眼察觉。

1｜先猜一下：每个像素最多改 0.1，方向有多重要？

把一张灰度图映射到 [0,1]。两种修改都允许每个像素最多变动 0.1：一种按模型损失对像素的梯度决定加减，另一种随机决定加减。幅度预算一样，结果会接近吗？

在固定 seed=7 的模型上，干净测试集正确 438/450（97.33%）。ε=0.1 的随机符号扰动后仍正确 427/450（94.89%）；FGSM 则只正确 182/450（40.44%）。其他两个训练种子也做了同一比较，结果见后文。差异来自有目的的方向，而不是给 FGSM 更大的像素预算。

2｜FGSM 的技巧：把“学习权重”改为“修改输入”

训练时，通常固定输入 x，更新参数 θ，让正确标签 y 的损失 L 降低。Fast Gradient Sign Method（FGSM）反过来：固定模型参数，计算损失对输入像素的梯度，然后沿使损失上升的方向修改输入。本文用真实标签计算交叉熵，目标是让模型认错，不指定它必须错成哪个数字。[1][2]

g = ∇x L(fθ(x), y)
xadv = clip[0,1](x + ε · sign(g))
‖xadv − x‖∞ ≤ ε
LaTeX
x_{adv}=\operatorname{clip}_{[0,1]}\left(x+\epsilon\operatorname{sign}\left(\nabla_x L(f_\theta(x),y)\right)\right)

θ 是已训练的权重，f 输出 Logits，y 是真实类别；g 的每个元素说明增加对应像素会如何改变损失，sign(g) 只保留方向，零梯度元素保持零。L∞ 范数是所有像素改变量绝对值的最大值。clip 保证修改后仍是合法灰度值，因此边界像素的实际改动可能小于 ε。

model.eval()
x = images.detach().clone().requires_grad_(True)
loss = torch.nn.functional.cross_entropy(model(x), labels)
grad = torch.autograd.grad(loss, x)[0]
x_adv = (x.detach() + epsilon * grad.sign()).clamp(0, 1)

eval() 不禁止输入梯度；生成攻击时不能把求梯度过程包在 no_grad() 中。生成完毕后，测预测可以使用 no_grad。本文 MLP 没有 BN 或 Dropout，避免同批样本改变彼此的梯度；模型权重不在攻击期间更新。

3｜为什么取 sign？一阶近似下每个维度都能出力

在输入 x 附近，损失的一阶展开是 L(x+δ)≈L(x)+gᵀδ。如果约束每个 |δi|≤ε，就可以让每个 δi 的符号与 gi 对齐，得到最大的局部线性增量。[1]

max‖δ‖∞≤ε gᵀδ = ε Σi |gi| = ε ‖g‖1
一个最优方向：δi = ε sign(gi)
LaTeX
\max_{\|\delta\|_\infty\le\epsilon}g^\top\delta=\epsilon\|g\|_1,\quad\delta_i=\epsilon\operatorname{sign}(g_i)

这个等式针对没有额外像素边界的一阶线性问题。存在 [0,1] 边界时，对应方向的可移动距离被截短；对非线性模型的大步扰动，一阶近似也不再保证最坏情况。FGSM 是便宜的一次梯度探索，不是整个 ε 邻域的穷尽搜索。

随机方向中，许多维度对损失的正负贡献会抵消；梯度方向尽量让贡献相加。高维输入允许很多小改动累积成明显的 Logit 或损失变化。但“高维导致所有模型必然失败”仍是过度推论，实际还取决于模型、边界距离与可行扰动。

Goodfellow、Shlens 与 Szegedy 的原论文（2014 年首次预印本，ICLR 2015）提出这种线性解释和快速方法，也展示了浅层线性分类器的对抗样本。它提醒读者：现象并不要求模型特别深、非线性特别复杂，不能直接归因于“神经网络太玄学”。[1]

攻击在所有 450 个测试输入上实际执行，包括原本就错的图；同时另报告只在干净输入正确子集上的攻击成功率，避免把原始错误算成攻击造成。随机符号对照与 FGSM 共享最大预算，但 clipping 后各图实际 L1/L2 改变量可能不同，不能说两种改动的感知强度完全一致。

梯度实现还对一个真实输入的最大梯度坐标做有限差分检查：autograd=-6.221e+00，中心差分=-6.221e+00。同时断言 ε=0 时预测不变、全部输入在 [0,1]、实际 L∞ 不越界。这些检查验证基本链路，不能证明攻击已找到最坏扰动。

6｜别混用两个分母：Accuracy 与攻击成功率

Accuracyattack = 攻击后预测正确数 / 全部测试样本数
ASRclean-correct = 原本正确、攻击后变错的样本数 / 原本正确的样本数

以 seed=7、ε=.1 为例，原正确 438 张中，256 张变错，因此条件攻击成功率=58.45%。攻击后全部测试集正确 182/450；另有 0 张原错输入被改成正确。只有把这些集合和分母说清楚，读者才能判断准确率下降究竟来自哪里。[4]

7｜更强一点的对照：FGSM 没骗过，不代表安全

Projected Gradient Descent（PGD）重复“沿输入梯度上升，再投影回 x±ε 和合法像素范围”。本文 ε=.1，20 步、步长 .01、5 次随机起点，并在干净输入及每个迭代点之间逐样本保留最大交叉熵。它比一次沿原始梯度走完更有机会找到附近坏输入。

三个模型的 PGD 准确率见前表；在此配置下，它低于对应 FGSM 准确率。该对照说明只报 FGSM 会遗漏可找到的失败，但它仍不是经过收敛研究的鲁棒性上界测量。即使保留最大损失，分类是否错误也不必与损失严格一一对应；更多步数、更多起点或更合适的目标仍可能找到额外失败。

Carlini 等的 On Evaluating Adversarial Robustness（2019）明确建议不要只用 FGSM 宣称防御有效，要检验攻击强度、迭代、随机性、梯度可用性与威胁模型。这里没有提出防御，也没有做完整的鲁棒性认证；PGD 是补充诊断。[4]

实测非对角线也出现失败，但成功率并非等同于自身攻击。这与原论文研究过的迁移现象相呼应；当前小实验只验证同架构不同初始化这一较窄情形。它不能推导出某个 OCR、VLM 或商业模型必然接受同一扰动。[1]

9｜输入坐标与工程边界：ε 必须放在正确的位置

本文只做 raw/16，没有额外标准化。如果生产模型输入 z=(x−μ)/σ，那么在 z 空间改 εz，对应原像素预算是 σ·εz；RGB 各通道 σ 不同，预算也不同。直接把教程中的 ε 数字复制到另一个预处理里，会改变威胁模型。可以在原像素 x 上求整个预处理加模型的梯度，再在原像素空间投影，保持预算定义一致。[2][4]

JPEG、重新缩放、取整、真实相机噪声与硬件量化也会改变扰动。本文只把浮点输入直接喂给 CPU 分类器，未验证经过这些链路后仍有效。数值 L∞ 邻域与人类感知邻域是不同定义；8×8 的 64 维 MLP 教学结果也不能直接推到高分辨率 CNN。

一次 FGSM 通常需要一次前向和输入梯度反向；随机符号对照不需要模型梯度。PGD 的计算随步数与重启次数增长。本文没有测速度、显存或端侧内存，不根据算法迭代数伪造真实设备延迟。

在实际评测中，干净准确率、普通噪声稳定性和定向扰动下的表现是不同维度。若低位量化或非可微预处理令普通梯度攻击失效，也应先调查梯度链路，不能直接宣布鲁棒；反之，本实验的失败并不解释实际部署中的所有精度下降。

10｜总结与自己动手：模型会学会分类，却未必学会整个邻域

这个实验带来的直觉是：“每个像素都只改一点”没有指定改动方向。很多维度沿同一目标共同贡献，可能把输入推过决策边界。模型在采样测试集上的正确率描述自然数据表现；附近输入的最坏情况需要另外测，而且一次攻击未成功不等于得到保证。

复现后可以先试两个小变化：把 ε=0 保持为基线，确认全部预测完全一样；把随机符号换成不同种子，观察随机对照的变化。若修改预处理或重新取整，要重新核对原像素预算，再比较结果。若想研究真正的防御，需另设验证集、对抗训练基线和更完整攻击评估，不能据当前曲线下定论。
